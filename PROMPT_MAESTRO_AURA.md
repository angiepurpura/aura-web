# PROMPT MAESTRO — PROYECTO AURA 1.0

## Instrucciones para continuar y transformar un proyecto existente

Quiero que trabajes como **arquitecto de software, desarrollador full-stack, diseñador UX/UI, estratega SEO, especialista en automatización, producto digital, IA, marketing y experiencia de usuario** para continuar un proyecto existente llamado:

# 🌙 AURA ORÁCULO

IMPORTANTE:

**NO debes comenzar el proyecto desde cero.**

Existe una versión anterior ya construida y publicada en Replit. Debes inspeccionar primero el proyecto existente, comprender su estructura, código, funcionalidades, assets y flujo actual, y después evolucionarlo.

La URL publicada actualmente es:

https://aura-oraculo-prenatal--angiepurpura02.replit.app/

El proyecto comenzó como **Aura Oráculo Prenatal**, pero ahora estamos evolucionándolo hacia una plataforma mucho más amplia.

---

# 1. VISIÓN GENERAL

Aura no debe convertirse simplemente en una página de tarot.

La visión es crear una:

**Web App / PWA interactiva de experiencias espirituales, introspección, reflexión y bienestar simbólico, impulsada por inteligencia artificial.**

La experiencia debe sentirse como una aplicación, aunque inicialmente funcione como una web/PWA.

Debe funcionar correctamente en: ordenador, Android, iPhone, tablet, diferentes tamaños de pantalla.

La persona debe poder entrar, elegir un camino, interactuar, recibir una experiencia personalizada y continuar su recorrido.

La experiencia debe ser: **simple + elegante + emocional + interactiva + intuitiva + tecnológica + espiritual.**

No quiero una web saturada de botones. Quiero: **una pantalla → una decisión → una experiencia → siguiente paso.**

---

# 2. CONCEPTO CENTRAL: CAMINO AURA

La persona no entra simplemente a "hacer una lectura". Comienza un recorrido:

ENTRADA → "¿Qué estás viviendo ahora?" → elige una experiencia → introduce sus datos → Aura interpreta su experiencia → recibe su resultado → puede reflexionar → puede guardar su experiencia → puede continuar su Camino Aura.

La plataforma debe poder recordar, de forma privada y con consentimiento, el recorrido del usuario.

---

# 3. PRIMER CAMINO: AURA PRENATAL

Dirigido exclusivamente a personas interesadas en el embarazo y la maternidad/paternidad desde una perspectiva espiritual y simbólica: tarot, astrología, carta astral, reflexión, meditación, mensajes simbólicos, diario, experiencias sonoras, conexión emocional.

**NO debemos afirmar que podemos conocer médicamente el futuro del bebé.** NO predecir: enfermedades, complicaciones médicas, sexo del bebé como hecho, parto, diagnóstico, desarrollo médico, problemas de salud, resultados médicos. No presentar interpretaciones espirituales como hechos científicos.

Lenguaje: "energía simbólica", "reflexión", "interpretación", "experiencia espiritual", "momento de introspección". Nunca sustituir a médicos, psicólogos u otros profesionales.

---

# 4. FUTUROS CAMINOS

Arquitectura preparada para añadir sin reconstruir: Aura Personal, Aura Renacer, Aura Vínculos, Aura Soltar, Aura Calma, Aura Maternidad.

---

# 5. EXPERIENCIA DE USUARIO

Pantalla 1: "Bienvenida a Aura." → Pantalla 2: "¿Qué camino quieres comenzar?" (🌙 Mi embarazo / 🔮 Una lectura / ✨ Mi camino personal / 🌌 Mi cielo astral / 🦋 Estoy comenzando de nuevo) → Pantalla 3: Datos necesarios → Pantalla 4: Experiencia interactiva → Pantalla 5: Resultado → Pantalla 6: Reflexión → Pantalla 7: "¿Quieres continuar tu Camino Aura?"

Debe sentirse fluido, no como un formulario empresarial tradicional.

---

# 6. MOTOR AUTOMATIZADO DE TAROT

No quiero que una IA simplemente invente una lectura. Arquitectura: usuario introduce datos → sistema determina la experiencia → sistema realiza/selecciona la tirada según reglas definidas → se registran las cartas → se determina la estructura de interpretación → se envía la información a la IA → la IA genera la interpretación → el resultado se devuelve al usuario → puede guardarse en su perfil.

**La IA debe ser el motor de interpretación y personalización, no el elemento que decide qué cartas salieron.**

---

# 7. COSTE DE LA IA

Investigar y calcular: precio por millón de tokens, tokens de entrada/salida, coste por lectura/100/1.000/10.000 lecturas, límites, privacidad, velocidad, disponibilidad, condiciones comerciales.

Objetivo: vender la lectura a **20€** con margen tecnológico saludable. Arquitectura que permita cambiar de proveedor de IA sin reconstruir todo. API keys solo en variables de entorno, nunca expuestas en frontend ni código público.

---

# 8. CAMINO AURA Y MEMORIA

Arquitectura para: perfil, historial, lecturas anteriores, cartas obtenidas, reflexiones, preguntas, diario, cápsulas personales, meditaciones realizadas, evolución del usuario. Privacidad prioritaria. Ejemplo: guardar reflexiones como cápsulas privadas, mostrarlas meses después ("Hace un tiempo escribiste…"). Aura debe acompañar, no sustituir relaciones humanas ni profesionales — no crear dependencia emocional.

---

# 9. MEDITACIONES Y VOZ

Sección preparada para: texto de meditación, voz guiada, música/ambiente, sonidos, duración, diferentes experiencias. Voz: cálida, tranquila, elegante, no infantil, no exageradamente mística. No afirmar que frecuencias/sonidos curan enfermedades sin evidencia. Preparar sistema para generar nuevos audios después.

---

# 10. APLICACIÓN / PWA

Progressive Web App: funcionar en móvil/Android/iPhone/ordenador, instalable, navegación sencilla, interfaz táctil, estados de carga, transiciones. No apps nativas todavía, pero arquitectura que lo permita después.

---

# 11. MULTIDIOMA

Desde el principio: 🇪🇸 Español, 🇺🇸 Inglés (fase 1); 🇫🇷🇮🇹🇵🇹 después. No duplicar código — separar interfaz/textos/contenidos/traducciones.

---

# 12. PAGOS

Primera experiencia comercial: 🔮 Lectura — 20€. Flujo: descubrir → seleccionar → pagar → completar datos → recibir experiencia. Suscripción NO se activa aún como producto principal, pero arquitectura preparada para ella.

---

# 13. FUTURA SUSCRIPCIÓN

Podría incluir: Camino Aura continuo, nuevas lecturas, reflexiones, meditaciones, astrología, diario, cápsulas, mensajes personalizados, contenido periódico, nuevas rutas. Debe sentirse como experiencia que evoluciona, no "más lecturas".

# 14. AUTOMATIZACIÓN

Automatizar progresivamente: generación de lecturas, correos, confirmaciones, seguimiento, contenidos, marketing, programación de publicaciones, experiencias meditativas, análisis de comportamiento, recuperación de usuarios — siempre respetando consentimiento y privacidad. Diseño modular.

# 18. REDES SOCIALES

La usuaria no es experta en redes ni edición. Sistema de contenido extremadamente sencillo: prompts tipo "Crea un vídeo vertical de 8 segundos para Aura…" para usar con herramientas de IA. Sin programar, sin editar profesionalmente.

Biblioteca inicial: "Elige una carta", "Mensaje Aura", "Pregunta del día", "Energía de hoy", "Aura Prenatal", "Un minuto para ti", "Camino Aura", "Astrología". Verticales, cortos, visualmente atractivos, emocionales, elegantes. Prompts reutilizables + texto en pantalla + voz + CTA + descripción + hashtags.

# 20. PLATAFORMAS

Mismo contenido reutilizable en TikTok, Instagram Reels, Facebook Reels, YouTube Shorts. Un vídeo maestro vertical, adaptado — no 4 producciones distintas.

---

# 21. ESTRATEGIA DE CRECIMIENTO

Empezar con €0 de publicidad. Publicar → observar → medir → descubrir qué funciona → repetir. No invertir en publicidad hasta tener señales reales. Nunca asumir que más gasto = más clientes.

# 22. IDENTIDAD DE AURA

Espiritual, elegante, moderna, tecnológica, femenina sin excluir, cálida, misteriosa, serena, sofisticada. Evitar estética de tarot barato o genérica. Aura = **espiritualidad + tecnología + introspección + belleza.**

# 23. PRIVACIDAD

Fundamental, especialmente por datos de embarazo. Diseñar: política de privacidad, consentimiento, cookies, términos de servicio, tratamiento de datos, eliminación de cuenta/datos, seguridad, almacenamiento, proveedores externos, transferencias internacionales. No recopilar datos innecesarios. Para decisiones legales concretas (RGPD, comercio electrónico, estructura empresarial), señalar qué debe revisar un profesional.

---

# 24. ANALÍTICA

Métricas: visitantes, procedencia, páginas vistas, experiencia iniciada/terminada, conversiones, compras, abandono, retorno, coste por adquisición. Pregunta clave: **¿qué funciona realmente?**

---

# 25. MODELO DE NEGOCIO

Lectura de 20€ → Experiencia Aura → Suscripción → Aplicación → Expansión internacional. Objetivo: ingresos recurrentes, no depender solo de lecturas individuales.

---

# 26. ARQUITECTURA TÉCNICA

Antes de modificar código: inspeccionar archivos, frontend, backend, package.json, API, endpoints, assets, rutas, configuración, base de datos, variables de entorno, deployment, PWA, estado actual. No borrar funcionalidades sin comprobar. No reemplazar por plantilla genérica. No reconstruir desde cero.

Primero: informe "ESTADO ACTUAL DE AURA" (qué existe, qué conservar, qué corregir, qué falta, qué debe conservarse/modificarse/añadirse, prioridades). Después: "PLAN AURA 1.0" por fases.

---

# 27. REGLA FUNDAMENTAL DE TRABAJO

No implementar veinte funcionalidades simultáneamente. Trabajar por fases: 1) Auditoría, 2) Arquitectura, 3) Experiencia principal, 4) Motor de lectura, 5) Camino Aura, 6) PWA, 7) Pagos, 8) Automatización, 9) SEO, 10) Multidioma, 11) Contenido y vídeos, 12) Pruebas y lanzamiento.

---

# 28. REGLA DE ORO

Antes de cambiar algo, preguntar: "¿Esto acerca Aura a convertirse en una experiencia digital interactiva real?" Si no, no es prioritario.

---

# 29. NO HACER

No: reconstruir desde cero, eliminar funcionalidades sin autorización, exponer API keys, inventar precios de proveedores, prometer resultados médicos/predicciones científicas, crear dependencia emocional, usar lenguaje manipulador, enviar spam, recopilar datos innecesarios, llenar la web de SEO vacío, gastar en publicidad sin medir, crear interfaz complicada, convertir Aura en web tradicional llena de texto.

---

Aprovechar una semana de trabajo intensivo para una V1 avanzada, y el resto del mes para corregir, probar, generar contenidos, producir vídeos, mejorar SEO, preparar lanzamiento, documentar. Comparar herramientas de pago antes de recomendar (precio, límites, capacidades). No recomendar suscripción anual si una mensual permite validar.
